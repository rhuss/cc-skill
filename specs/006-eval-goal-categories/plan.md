## Global Constraints

These constraints apply to every task and are inherited implicitly:

- **No agent-eval-harness changes**: All modifications are within this plugin's eval configs and scripts. The harness schema is not modified.
- **Judge naming is convention-only**: The harness treats judge names as opaque strings. Prefixing is enforced by this plugin, not the harness.
- **Backward compatibility**: Existing eval cases must run without modification. New fields (e.g., `invocation_type`) default to safe values.
- **Platform**: macOS/Linux CLI. Scripts must be sh-compatible (bash with `set -euo pipefail`).

## Implementation Approach

### Phase 1: Judge Reorganization (FR-001, FR-002, FR-003, FR-004, FR-011)

**skill-check judge mapping:**

| Old Name | New Name | Category | Type |
|----------|----------|----------|------|
| budget_check | efficiency_budget | efficiency | builtin |
| checklist_completeness | outcome_checklist_completeness | outcome | deterministic (check) |
| status_validity | outcome_status_validity | outcome | deterministic (check) |
| note_specificity | style_note_specificity | style | model-assisted (prompt) |
| pattern_accuracy | outcome_pattern_accuracy | outcome | model-assisted (prompt) |
| (new) | process_evaluation_sequence | process | deterministic (check) |
| (new) | style_summary_format | style | deterministic (check) |

New judges for skill-check:
- `process_evaluation_sequence`: Deterministic check verifying the skill produced an activation test section with both trigger and non-trigger scenarios (evidence of following the documented evaluation procedure).
- `style_summary_format`: Deterministic check verifying the summary line matches the expected pattern `N of M applicable patterns present, X strong, Y improvements suggested`.

**skill-enhance judge mapping:**

| Old Name | New Name | Category | Type |
|----------|----------|----------|------|
| budget_check | efficiency_budget | efficiency | builtin |
| output_completeness | outcome_output_completeness | outcome | deterministic (check) |
| pattern_evaluation | outcome_pattern_evaluation | outcome | deterministic (check) |
| frontmatter_preserved | outcome_frontmatter_preserved | outcome | deterministic (check) |
| changelog_specificity | style_changelog_specificity | style | model-assisted (prompt) |
| proportionality | style_proportionality | style | model-assisted (prompt) |
| intent_preservation | outcome_intent_preservation | outcome | model-assisted (prompt) |
| (new) | process_step_execution | process | deterministic (check) |

New judge for skill-enhance:
- `process_step_execution`: Deterministic check verifying the "Steps Executed" section is present and lists executed steps.

### Phase 2: compare-runs.sh Updates (FR-005, FR-006, FR-007, FR-010, FR-012, FR-013)

Modify `compare-runs.sh` to:

1. **Extract category from judge name**: Split on first underscore. `outcome_checklist_completeness` yields `outcome`. Names without underscore go to `other` with stderr warning.

2. **Group terminal output by category**: Instead of a flat judge table, group under category headings (Outcome, Process, Style, Efficiency, Other).

3. **Per-category summary**: After the table, emit a summary line like `Category summary: Outcome: Improved, Process: Unchanged, Style: Unchanged, Efficiency: Unchanged`.

4. **Markdown report**: Same grouping in `comparison.md`.

5. **JSON output**: Write `comparison.json` to the enhanced run directory with the schema from FR-010. Best-effort (warn on write failure, don't fail the script).

### Phase 3: Invocation Type Annotations (FR-008, FR-009, FR-014)

1. Add `invocation_type: explicit` to all existing `annotations.yaml` files (10 files total: 5 skill-check cases + 5 skill-enhance cases).

2. Update the `dataset.schema` section in both `eval.yaml` files to document the new field.

3. Add `by_invocation_type` section to `comparison.json` generation in `compare-runs.sh`. When summary.yaml includes per-case metadata with invocation types, group results by type.

### Phase 4: Documentation Updates

1. Update `eval/skill-check/eval.yaml` description to reference 17 patterns (currently says 14).
2. Update `skill/skills/measure/SKILL.md` if it references specific judge names.
3. Update `skill/CLAUDE.md` if it references pattern counts.
